# POLAZU Editor V3 — Alpha × Beta 디자인 리뷰

이 문서는 구현 과정에서 사용한 **가상의 제품 리뷰 회의록**이다. Alpha는 코드·소스 보존·동시성·Git 흐름을 책임지는 시니어 프론트엔드 개발자, Beta는 실제 디자이너의 조작 속도·정보 위계·캔버스 집중도를 집요하게 검토하는 시니어 프로덕트 디자이너로 설정했다.

기준 화면은 `docs/screenshots/editor-before-actual.png`이며, 최종 화면은 `docs/screenshots/editor-v3-actual.png`이다. 둘 다 이미지 생성물이 아니라 실제 React 컴포넌트와 CSS를 Chromium에서 렌더링한 결과다.

## 1차 리뷰 — 기존 화면은 왜 작업 도구처럼 느껴지지 않는가

**Beta:** 기능이 없는 게 문제가 아니다. 모든 기능이 동시에 비슷한 강도로 보이는 게 문제다. 캔버스보다 툴바, 패널, 저장 버튼이 더 크게 소리치고 있다.

**Alpha:** 기존 구조는 편집 기능을 빠르게 붙이는 데 집중해서 상단에 보기 설정, 실행 취소, 확대·축소, 저장을 모두 나열했다. 실제 소스 연결과 서버 저장은 동작하지만 작업 위계가 없다.

**Beta:** 오른쪽 아래의 주황색 `변경 기록` 버튼은 특히 잘못됐다. 사용자는 변경이 버튼을 눌러야 캔버스에 반영된다고 오해한다. 디자인 툴에서는 조작 결과가 즉시 보여야 하고 저장은 배경 상태여야 한다.

**Alpha:** 캔버스 반영과 서버 저장을 분리하겠다. 시각 변경은 즉시 적용하고, 1.4초 유휴 후 공동 작업 초안에 자동 저장한다. 사용자가 명시적으로 해야 하는 최종 행동은 Git 게시로 남긴다.

**Beta:** 하단 선택 툴바도 캔버스와 멀리 떨어져 있다. 선택한 요소의 조작은 선택 영역과 가까운 컨텍스트 바에 있어야 한다. 뷰포트·확대·스냅 같은 보기 설정은 별도의 캔버스 독으로 내려라.

**결정**

- 캔버스를 제품의 시각적 중심으로 둔다.
- 상단은 프로젝트·모드·협업·게시만 담당한다.
- 요소 조작과 캔버스 보기 설정을 서로 다른 도구막대로 분리한다.
- 저장 CTA를 제거하고 `Autosave / Saved / View only` 상태로 낮춘다.
- `Publish`만 강한 명시적 행동으로 유지한다.

## 2차 리뷰 — Insert는 목록이 아니라 공간 조작이어야 한다

**Beta:** 24개 UI 요소가 있어도 클릭해서 현재 선택 컨테이너에만 들어가면 디자이너는 위치를 예측해야 한다. 그것은 폼 빌더이지 캔버스 도구가 아니다.

**Alpha:** 클릭 삽입은 키보드 사용자와 빠른 조작을 위해 유지하되, 드래그 데이터를 `application/x-polazu-insert`로 전달하고 캔버스 좌표를 iframe 좌표로 변환하겠다. 브리지에서 `elementFromPoint`를 사용해 드롭 위치의 가장 가까운 안전 컨테이너를 찾고 그 안에 삽입한다.

**Beta:** 드롭 중에는 캔버스 전체가 반응해야 한다. 사용자가 실제 페이지 위에 놓지 않았으면 조용히 실패하지 말고 안내해야 한다.

**Alpha:** 드래그 상태를 편집기 루트에서 추적해 drop surface를 표시하고, 페이지 밖에 놓은 경우 명시적인 알림을 보낸다. 실제 페이지 내부라면 가장 가까운 `main`, `section`, `div`, `article`, `nav`, `form`, 목록 계열 컨테이너에 추가한다.

**결정**

- 24개 primitive 모두 클릭 삽입과 드래그 삽입을 지원한다.
- 드롭 위치를 실제 페이지 좌표로 변환한다.
- 안전한 컨테이너를 찾지 못하면 `body`를 명시적 fallback으로 사용한다.
- 삽입은 기존 source-patcher 이력을 사용해 Undo와 저장 흐름에 포함한다.

## 3차 리뷰 — 패널은 기능 분류가 아니라 사용자의 질문에 답해야 한다

**Beta:** 왼쪽 패널 제목이 항상 프로젝트명만 보여주면 현재 무엇을 보고 있는지 알 수 없다. 디자이너의 질문은 “레이어가 몇 개인가?”, “삽입 요소가 몇 개인가?”, “토큰이 몇 개인가?”다.

**Alpha:** 앱 레일은 Layers, Insert, Tokens, Pages, Files의 모드를 유지하고, 컨텍스트 패널 헤더는 현재 탭과 수량을 표시하겠다. 프로젝트 기술 스택과 루트 선택은 그 아래의 보조 컨텍스트로 내린다.

**Beta:** 오른쪽 패널은 읽을 수 있어야 한다. 12px 미만의 제어가 과도하고, 패널 폭이 좁아서 CSS 값을 읽기 어렵다.

**Alpha:** 기본 오른쪽 패널을 360px, 왼쪽 패널을 316px로 확대한다. 캔버스는 `minmax(320px, 1fr)`로 남기고, 1366×768에서도 문서 자체 overflow가 생기지 않도록 검증한다.

**결정**

- 좌측 앱 레일과 컨텍스트 패널을 분리한다.
- 선택·삽입·토큰·페이지·파일은 같은 영역에서 모드 전환한다.
- 오른쪽은 Design / Code / Mock / Audit의 전문 작업 패널로 유지한다.
- 협업, 버전, 리뷰, 팀, Git은 상시 고정 패널이 아니라 필요할 때 여는 drawer로 이동한다.

## 4차 리뷰 — 혁신은 기능 수가 아니라 상태의 명료함에서 나온다

**Beta:** 사용자는 “내 화면에 보이는 변경”, “서버에 저장된 초안”, “리뷰할 변경”, “Git에 게시된 변경”을 구분해야 한다. 이 상태가 흐리면 협업 도구로 신뢰할 수 없다.

**Alpha:** 상단에 다음 상태를 분리한다.

- `Autosave · N`: 현재 캔버스에는 적용됐지만 서버 저장 대기 중인 변경
- `Autosaving…`: 서버에 전송 중
- `Saved · rN`: 현재 revision까지 공동 작업 초안에 반영됨
- `Publish N`: 게시되지 않은 revision 수. 클릭 시 Git drawer 열기
- `Review`: 댓글·수정 요청 drawer 열기

**Beta:** 좋다. 저장과 게시를 절대로 같은 색과 같은 단어로 표현하지 마라.

## 최종 제품 원칙

1. **Immediate canvas** — 모든 시각 조작은 저장 버튼 없이 즉시 보인다.
2. **Source-linked, not canvas-only** — 선택 요소는 실제 파일·소스 위치와 연결된다.
3. **Spatial insertion** — UI 요소는 목록에서 선택하는 것뿐 아니라 원하는 위치로 드래그한다.
4. **Progressive disclosure** — 요소 도구, 캔버스 보기, 협업, Git을 서로 다른 계층에 둔다.
5. **Safe by default** — 동적 JSX나 의미 보존이 불확실한 변경은 성공으로 가장하지 않는다.
6. **Autosave is a state, Publish is an action** — 공동 초안 저장과 Git 게시를 명확히 구분한다.
7. **Canvas first** — 패널은 캔버스를 보조하며 캔버스보다 강한 시각적 무게를 갖지 않는다.

## 리뷰 결과가 반영된 코드

- `DesignerToolbar.tsx`: 제품 상단 바, 실제 접속자 presence, 캔버스 독, 수직 도구막대, 선택 컨텍스트 바
- `DesignerSidebar.tsx`: 앱 레일, 탭별 수량, 24개 draggable primitive
- `DesignerInspector.tsx`: 저장 CTA 제거, Live preview 상태 표시
- `BrowserProjectRuntime.tsx`: 자동 저장, fit selection, drop 좌표 처리, workspace drawer 연결
- `WorkspaceDock.tsx`: Review / Team / Git의 요청형 drawer
- `editor-bridge.js`: 위치 기반 primitive 삽입과 Link primitive
- `page.css`: 전체 화면 작업 공간과 반응형 패널 재설계

## 의도적으로 완료라고 표시하지 않은 영역

- 가져온 프로젝트 컴포넌트 자동 발견과 props/variant 시각 편집
- 동적 JSX 반복 렌더링의 개별 인스턴스 구조 변경
- 문자 단위 CRDT/OT
- 이미지 바이너리 업로드·crop·팀 자산 라이브러리
- 모션 타임라인과 상태 머신
- 전체 Next.js 런타임을 사용한 실제 브라우저 E2E
