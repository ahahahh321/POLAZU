# 공유 프로젝트를 내 IDE에서 수정하기

이 문서는 개발 후 사용 흐름이다. 서비스 설치/SQL 반영은 `MIGRATION.md`를 먼저 따른다.

## 1. 소유자: 프로젝트 공유

1. POLAZU 계정으로 로그인한다. Spring API와 DB가 실행 중이어야 한다.
2. 에디터에서 GitHub 저장소 또는 소스 ZIP을 가져온다. GitHub 비공개 저장소는 본인의 읽기 권한 토큰이 필요하다.
3. `팀 공유` → `새 팀 프로젝트로 공유`를 누른다. 허용된 소스·자산이 서버에 저장된다는 확인을 읽는다.
4. 가입된 팀원의 이메일로 수정자 또는 뷰어 초대 토큰을 만든다. 자동 메일이 아니므로 해당 팀원에게만 전달한다.
5. 이미 생성한 빈 프로젝트에서 최초 소스 업로드가 실패했다면, 선택한 빈 프로젝트에 공유 재시도 버튼을 사용한다. 기존 소스가 있으면 덮어쓰지 않고 열기를 사용한다.

## 2. 팀원: 공유 프로젝트 열기

로그인 후 `팀 프로젝트 열기`에서 초대 수락 → 목록의 프로젝트를 선택한다. ZIP을 팀원마다 다시 업로드할 필요가 없다. 목록/ID로 서버의 같은 작업본을 연다.

## 3-A. 폴더 직접 연결이 가능한 환경

`⇄ 동기화` → **빈 폴더로 내려받고 IDE 연결** → 새 빈 폴더 선택 → 브라우저의 읽기/쓰기 권한 승인.

선택한 폴더에 파일을 복사하고 연결한다. 폴더를 VS Code, WebStorm 등 원하는 IDE로 열고 저장하면 웹 화면과 팀에 자동 반영한다. 반대 방향의 승인된 웹/팀 수정도 같은 폴더에 반영한다.

기존 파일이 조금이라도 있는 폴더에는 최초 체크아웃하지 않는다. 다시 방문했을 때는 같은 공유 프로젝트를 연 다음 **기존 연결 폴더 다시 연결**을 누른다. 이전 공통 기준과 오프라인 저장을 비교하므로 폴더를 매번 새로 덮어쓰지 않는다.

API는 브라우저/보안 환경에 따라 제공되지 않을 수 있다. HTTPS 또는 개발용 신뢰 가능한 로컬 환경과 사용자 클릭/권한 승인이 필요하다. 폴더 접근 창을 웹사이트가 승인 없이 자동으로 띄우거나 임의 폴더를 읽는 기능이 아니다.

## 3-B. 직접 연결 API가 없거나 차단된 환경

`⇄ 동기화` → **IDE용 ZIP 받기 · 연결 도구 포함**.

새 폴더에 압축을 풀어 IDE로 연다. Node.js 22 이상이 있는 PC에서 그 폴더의 터미널로 다음을 실행한다.

```bash
node .polazu-link/connect.mjs
```

터미널의 URL과 연결 토큰을 웹의 `연결 도구의 주소·토큰으로 연결`에 입력한다. 웹·팀 변경도 로컬 파일에 반영할 경우 쓰기 허용을 확인한다. 계정 비밀번호/GitHub 토큰이 아니라 이 연결 도구의 일회 실행 토큰을 입력한다.

연결 도구는 프로젝트 npm 명령을 실행하지 않는다. 프로젝트 자체 실행/테스트에 필요한 `npm ci`, `npm run dev` 등은 신뢰하는 코드임을 확인한 후 개발자가 별도로 실행한다. ZIP을 받는 것만으로 연결되는 것은 아니다.

로컬 네트워크 접근 권한/CORS/회사 브라우저 정책이 연결을 차단할 수 있다. 보안을 전역 해제하지 않는다. 승인 가능한 환경을 사용하거나 ZIP으로 수동 전달한다.

## 4. 개발하면서 알아둘 점

- **파일을 저장해야 한다.** IDE의 아직 저장하지 않은 탭/버퍼는 읽지 않는다.
- **개발자 쪽 POLAZU 탭을 열어둔다.** 연결 도구 방식은 터미널도 켜둔다. 웹 탭을 닫으면 팀 서버 중계가 멈춘다.
- 활성 로컬 확인 주기는 약 2초다. 팀은 활성 약 2초, 유휴 약 6초, 숨긴 탭은 10초 이상이다. 실제 전송·빌드·브라우저 제한 시간은 추가된다.
- 같은 파일을 웹과 IDE에서 동시에 수정하면 선택 화면에서 충돌을 해결한다. Git의 줄 단위 자동 병합이나 문자 단위 공동 편집과 같지 않다.
- 웹이 기존 로컬 파일을 바꾸기 전에 `.polazu-backups/`에 복사한다. IDE의 모든 저장을 버전 백업하는 기능은 아니다.
- `.polazu-link/`와 `.polazu-backups/`는 Git 커밋에서 제외한다. 전자는 프로젝트 연결 정보·소스 기준, 후자는 이전 소스를 포함한다. 토큰은 포함하지 않지만 비공개 코드가 있을 수 있다.
- 뷰어는 소스를 받을 수 있으나 서버의 코드/UI를 바꿀 수 없다. 다운로드한 개인 사본은 권한 회수로 지워지지 않는다.
- GitHub에서 왔어도 이번 체크아웃/IDE ZIP은 `.git` 없는 작업 사본이다. Git 이력이 필요하면 Git clone을 별도로 준비하고 기존 수동 에이전트 경로로 연결한다. 원격 반영은 검토 후 PR로 한다.

## 5. 가져오기 제한

| 항목 | 기본 제한 | 이유 |
|---|---:|---|
| 허용 소스+자산 | 32MiB | 브라우저 메모리·동기화 비용 제한 |
| 파일 하나 | 4MiB | 큰 바이너리·생성물 혼입 제한 |
| 허용 파일 수 | 2,500개 | 반복 파일 확인·렌더링 부담 제한 |
| 업로드 ZIP | 64MiB | 브라우저 압축 해제 부담 제한 |
| ZIP 해제 예상 크기 | 128MiB | 제외 항목도 포함한 해제 방어 |
| ZIP 전체 항목 수 | 12,000개 | 매우 많은 작은 항목 방어 |
| 소유 프로젝트 | 10개 | 초기 서버 저장 예산 제한 |

`node_modules`, `.git`, `.next`, `dist`, 빌드 결과, 실제 `.env`, 대표 자격증명, 연결 도구/백업은 공유 대상에서 제외한다. 코드에 직접 적은 비밀까지 모두 탐지한다고 보장하지 않으므로 공유 전 확인해야 한다. 처음 제공했던 약 400MiB 전체 개발 폴더 ZIP처럼 의존성까지 넣은 파일은 사용자 에디터 업로드 제한에 걸린다.

## 6. 연결이 안 될 때

| 증상 | 확인 |
|---|---|
| 직접 연결 버튼 비활성 | API/secure context 유무, 뷰어 여부, 팀 연결 여부 |
| 빈 폴더 경고 | 새 빈 폴더로 최초 받기, 이전 연결 폴더는 재연결 사용 |
| 다른 프로젝트 메시지 | 같은 서비스 origin/프로젝트 ID인지 확인. marker를 수동 조작하지 않기 |
| 소스 변경 충돌 | IDE와 웹 변경을 비교하고 보존할 버전을 명시적으로 선택 |
| 서버 401/403 | 재로그인/초대/현재 역할 확인. 로컬 작업은 남아 있음 |
| 서버 409/429 | 최신 버전 비교/백오프. 반복되면 다른 클라이언트 동시 편집 상태 확인 |
| 소스는 바뀌나 preview 오류 | 기존 런타임 지원·프로젝트 오류·의존성 검사. package 설정 변경은 명시적 재시작 필요 |
| 잘못 덮어쓴 것으로 보임 | 즉시 연결 해제 → 작업 폴더 별도 복사 → 백업/diff 비교. 백업 통째로 무조건 덮어쓰지 않기 |
